# MTK Music Visualizer

React + TypeScript + Vite, Web Audio API 및 Canvas 2D로 만든 MTK 음악 비주얼라이저 MVP입니다. 왼쪽 MTK 로고와 오른쪽 원형 스펙트럼을 실시간으로 렌더링합니다.

## 실행

Node.js 20.19+ 또는 22.12+와 FFmpeg(libx264 및 AAC 인코더 포함)가 필요합니다. macOS에서는 `brew install ffmpeg`로 설치할 수 있습니다. FFmpeg가 없으면 미리보기는 사용할 수 있지만 영상 출력은 비활성화됩니다.

MP4 출력에는 영상과 소리를 압축할 인코더가 필요합니다. 이 프로젝트는 FFmpeg의 `libx264`(H.264 영상)와 `aac`(AAC 오디오)를 사용하며, 운영체제용 코덱 팩을 별도로 설치할 필요는 없습니다. 앱 시작 시 두 인코더의 포함 여부를 확인하고, FFmpeg 실행 실패 또는 필요한 인코더 누락 시 화면에 이유를 표시합니다. 현재 구조에서는 FFmpeg 없이 MP4를 출력할 수 없습니다.

```sh
npm install
npm run dev
npm test
npm run build
npm run preview
```

## 사용

1. 음악 파일을 선택합니다. MP3, WAV, OGG 등의 지원 여부는 브라우저의 오디오 코덱에 따라 다릅니다.
2. 재생 버튼을 누르면 Web Audio 분석이 시작됩니다. 재생/일시정지, 탐색, 음량을 조절할 수 있습니다.
3. 원형, 막대형, 건반형 비주얼라이저를 선택합니다. 건반형은 피아노 모양의 주파수 표시이며 음정/MIDI 감지가 아닙니다.
4. Neon Pulse, Midnight Synth, Ocean Chill 프리셋을 선택하거나 링 색상과 민감도를 직접 조절합니다.
5. 배경 이미지 또는 배경 색상을 변경하고 전체 화면으로 미리봅니다.
6. 영상 텍스트에서 로고, 위쪽 문구, 슬로건, 비주얼라이저 문구, 하단 제목을 편집합니다. 빈 값은 숨겨지며, 새 음악을 선택하면 하단 제목이 파일명으로 초기화됩니다.
7. MP4 영상 만들기를 누르면 현재 설정을 고정하여 음악 처음부터 끝까지 출력합니다. 진행률을 확인하거나 취소할 수 있습니다. 완료되면 1시간 이내에 MP4 다운로드를 누릅니다.
8. 저장한 MP4를 YouTube Studio에 직접 업로드합니다.

미리보기의 오디오와 이미지는 로컬 object URL을 사용합니다. 영상 출력 시에는 이 컴퓨터의 루프백 서버(127.0.0.1)에 파일을 전달합니다. 외부 서버나 유튜브로 업로드하지 않습니다. 파일 교체 시 이전 URL을 해제합니다. 새로고침하면 선택한 파일과 설정은 초기화됩니다. 진행 중인 출력은 같은 탭에서 새로고침 후 다시 확인할 수 있습니다. 파일 선택 전에는 정적인 링이 표시됩니다.

## 구조

- `src/main.tsx`: UI, 오디오 그래프, Canvas 렌더링 및 리소스 수명 관리
- `src/presets.ts`: 프리셋, 주파수 에너지 계산, 시간 표시
- `src/render.ts`: 미리보기/영상 공용 스펙트럼 및 영상 합성
- `src/ExportPanel.tsx`: 영상 출력 요청, 상태, 취소, 다운로드
- `server/`: FFmpeg 기반 로컬 출력 서버 및 설정 검증
- `scripts/dev.mjs`: Vite와 로컬 출력 서버 함께 실행
- `src/style.css`: 반응형 스튜디오 화면
- `tests/`: 유틸리티, 출력 설정 검증, 세 가지 형태의 MP4 생성 및 오디오/코덱/길이 검증. 실제 출력 테스트는 FFmpeg와 ffprobe가 있을 때 실행됩니다.

브라우저 자동재생 정책에 따라 사용자의 재생 버튼 클릭으로 AudioContext를 시작합니다. 하나의 media element source를 재사용하고, requestAnimationFrame 종료 및 object URL 정리를 수행합니다. 모바일에서는 로고와 링을 위아래로 배치합니다.

## MP4 출력

출력은 1920×1080, 30fps, H.264 영상 + AAC 320kbps 오디오이며 MP4 Fast Start를 적용합니다. 녹화 방식이 아니라 프레임별로 Canvas를 합성하고 FFmpeg에 전달합니다. 재생 위치와 관계없이 전체 음악을 출력하며 오디오는 원본 음량을 사용합니다. 미리보기 음량은 출력에 영향을 주지 않습니다. 로고/배경/문구를 포함하고 앱의 조작 버튼은 영상에 포함하지 않습니다.

오디오 분석은 22,050Hz 모노 FFT, 출력 오디오는 원본 파일 기반으로 인코딩합니다. 미리보기와 출력은 동일한 스펙트럼 그리기를 사용하지만 분석 샘플레이트/글꼴 렌더러 차이로 반응이나 글자 모양은 조금 다를 수 있습니다. 시스템 글꼴을 사용하므로 한국어 텍스트에는 시스템에 한국어 글꼴이 설치되어 있어야 합니다.

- 음악 최대 2시간, 파일당 최대 512MB, 배경 최대 4천만 화소를 지원합니다.
- 한 번에 하나의 영상을 생성합니다. 시작 당시 설정이 적용되므로 출력 중 설정을 바꾸어도 현재 작업에는 반영되지 않습니다.
- 프레임은 인코더로 순차 전달해 이미지 전체를 메모리에 쌓지 않습니다. 분석용 PCM은 메모리에 보관하므로 2시간 음악은 분석 데이터에 약 635MB가 필요하며 시스템의 여유 메모리/디스크 공간이 필요합니다.
- 임시 업로드/분석 파일은 작업 종료 후 제거됩니다. 완료 MP4는 1시간 동안 다운로드할 수 있으며 이후 제거됩니다. 서버 종료 시 임시 작업을 정리합니다.
- 출력 서버는 127.0.0.1:4174에만 바인딩됩니다. FFmpeg 경로를 지정하려면 `MTK_FFMPEG` 환경 변수를 사용합니다.
- `npm run dev`가 두 서버를 함께 실행합니다. 빌드 결과 미리보기에는 별도 터미널에서 `npm run export:server`를 실행하고 `npm run preview`를 사용합니다. 정적 웹 호스팅만으로는 로컬 MP4 출력이 동작하지 않습니다.

## GitHub Pages 배포

기본 브랜치 `main`의 `docs` 폴더에 빌드 결과를 함께 저장합니다. 저장소의 Settings → Pages → Source를 **Deploy from a branch**, Branch를 **main**, 폴더를 **/docs**로 설정합니다. 배포 주소는 `https://waceh.github.io/music-visualizer/`입니다.

- 웹 버전은 음악 재생, 시각화, 배경 및 문구 편집을 지원합니다. 파일은 브라우저에서 처리합니다.
- GitHub Pages는 정적 호스팅이므로 로컬 FFmpeg 기반 MP4 출력은 지원하지 않습니다. 웹 버전에는 영상 저장 안내를 표시하며 출력 API를 호출하지 않습니다.

변경 사항을 배포하려면 `npm run build:pages`로 `docs`를 갱신하고 소스와 `docs`를 함께 `main`에 커밋·푸시합니다. 로컬 확인은 `npm run preview -- --outDir docs`로 실행합니다. `.nojekyll` 파일은 정적 빌드 결과를 그대로 제공하도록 지정합니다.

## 후속 단계

플레이리스트, 여러 음악 이어붙이기, 출력 해상도 선택, 프리셋/텍스트 저장을 확장할 수 있습니다. 유튜브 자동 업로드는 포함하지 않습니다.
